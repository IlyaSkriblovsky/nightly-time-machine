# Nightly Time Machine

Ночной бэкап MacBook на USB-диск через док-станцию. macOS 27. Приложение запускается системной службой; Full Disk Access выдан только приложению, не `/bin/bash`.

## Текущее состояние

Уже установлено и работает. Повторная установка после переноса проекта не нужна.

Подтверждено 31 октября 2026 (Asia/Nicosia, +0200), при закрытой крышке и подключённой док-станции:

- 02:00:06 — автоматическая разблокировка тома из System keychain.
- 02:00:08 — начало копирования.
- 02:07:55 — подтверждена новая завершённая копия; 7 611 162 624 байта.
- 02:07:56 — подтверждено размонтирование. Код завершения службы: 0.

Перенос исходников не меняет установленное приложение, подпись и разрешения.

## Устройство проекта

| Файл | Назначение |
|---|---|
| `Runner.swift` | Нативный запускатель: только встроенный сценарий, проверка root-владельца и прав, очищенное окружение |
| `backup.sh` | Разблокировка, монтирование, копирование, проверка новой копии и размонтирование |
| `app-daemon.plist` | Ежедневный запуск в 02:00 |
| `build-app.sh` | Сборка и ad-hoc подпись приложения в `build/` |
| `install.sh` | Чистая установка на настроенный Mac; отказывается заменять существующую установку |
| `setup-unlock.sh` | Сохранение/проверка ключа; не меняет приложение |
| `test-service.sh` | Однократный дневной запуск через настоящую службу |

`build/` и файлы редактора исключены из Git. Пароля, содержимого связки ключей и личных файлов в проекте нет. UUID — идентификаторы, не секреты. Git-репозиторий пока не инициализирован.

## Поведение

Пробуждение — 01:58, запуск — 02:00 по местному системному времени. Плановый запуск разрешён с 02:00 до 05:00. Это окно начала: длительный бэкап не обрывается в 05:00. Нет диска или питания от сети — пропуск. Другая копия уже идёт — пропуск. После ошибки выполняется обычное размонтирование; принудительное не используется. Если копирование ещё работает, сценарий оставляет том и пишет предупреждение.

Личный том не монтируется и не размонтируется сценарием. Если вы открыли My Backup вручную, перед отключением дока извлеките его отдельно. Сообщение об успешном размонтировании Mac Backup не означает, что личный том тоже закрыт.

Строка `Terminated: 15 caffeinate` после успеха штатна: сценарий завершает удержание от сна. Текущее поведение сохранено без пересборки рабочей установки. Индикатора menu bar пока нет.

## Проверка и диагностика

```sh
sudo ./test-service.sh
tail -f /var/log/local.nightly-time-machine.log
```

Ctrl+C останавливает только просмотр журнала. Ищите свежие SUCCESS и `Time Machine volume is unmounted`. Не запускайте второй тест во время копирования.

```sh
launchctl print system/local.nightly-time-machine
pmset -g sched
sudo cat /var/db/local.nightly-time-machine/last-success
```

`status` в том же каталоге описывает результат бэкапа, а не безопасность отключения всего диска. После аварийного завершения может остаться каталог `lock`; удалять его можно только после проверки, что служба и сценарий не выполняются.

## Чистая установка / восстановление

Эти команды не нужны на текущем Mac. Требуются Xcode или Command Line Tools со Swift. Сначала настройте диск в Time Machine, шифрование и первую копию; выберите ручную частоту. Проверьте UUID в исходниках.

```sh
./build-app.sh
sudo ./install.sh
sudo -H ./setup-unlock.sh
```

Установщик проверяет конфликты расписания и `/etc/fstab` и не форматирует диск. На установленной системе намеренно завершается без изменений. В случае ошибки посередине установки сначала проверьте журнал команды и оставшиеся файлы — это не транзакционный установщик.

В «Системные настройки → Конфиденциальность и безопасность → Полный доступ к диску» добавьте через «+» и Cmd+Shift+G:

```text
/Library/PrivilegedHelperTools/local.nightly-time-machine/Nightly Time Machine.app
```

Выберите установленную копию. Не давайте разрешение bash. После этого выполните `sudo ./test-service.sh`, затем проверьте ночной запуск с закрытой крышкой.

Пароль вводится скрыто и сохраняется в `/Library/Keychains/System.keychain`, service `local.nightly-time-machine.unlock`, account `root`. Доступ к этой записи разрешён `/usr/bin/security`, который передаёт пароль в diskutil через pipe. Сценарий временно выбирает System как связку по умолчанию для root, затем восстанавливает настройку. `sudo -H ./setup-unlock.sh --verify-existing` проверяет уже сохранённый ключ без повторного ввода.

## Изменения и обновление

Правки исходников сами по себе не меняют работающую установку. Сначала соберите `./build-app.sh` и проверьте результат. Для обновления остановите службу, сохраните предыдущую версию приложения и замените весь подписанный bundle с root:wheel и без записи для группы/остальных, затем загрузите службу. Автоматический update пока не реализован: `install.sh` намеренно отказывается перезаписывать установленное приложение.

Пересборка меняет ad-hoc подпись и может потребовать заново выдать Full Disk Access. Не редактируйте backup.sh внутри установленного подписанного приложения. Разрешение приложения распространяется на его рабочие дочерние процессы, но не даётся глобально системному bash.

## Отключение

Когда бэкап не выполняется:

```sh
sudo launchctl bootout system/local.nightly-time-machine
```

Это останавливает расписание запуска службы до следующей загрузки системы. Для постоянного удаления удалите её plist из `/Library/LaunchDaemons` и приложение из `/Library/PrivilegedHelperTools/local.nightly-time-machine`.

При желании вернуть автомонтирование удалите только две строки UUID проекта через `sudo vifs`. `sudo pmset repeat cancel` отменяет всё повторяющееся расписание питания: применяйте только если оно всё ещё принадлежит этому проекту. Ключ можно удалить командой:

```sh
sudo security delete-generic-password -a root -s local.nightly-time-machine.unlock /Library/Keychains/System.keychain
```

Не удаляйте сами тома или резервные копии. Системный журнал хранится в `/var/log/local.nightly-time-machine.log`, служебное состояние — в `/var/db/local.nightly-time-machine`.
